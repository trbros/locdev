# LocDev のアンインストール

登録済みプロジェクト、ログイン時の起動、アプリ全体のどれを削除するか決めてください。アプリの削除とプロジェクトのソースコードの削除は別です。ローカルデータを変更する前にバックアップしてください。

## プロジェクトだけを登録解除

`acme` を登録名に置き換えます。

```bash
locdev down acme
locdev remove acme
```

`remove` は登録を解除するだけで、プロジェクトのファイルを削除しません (`--delete-files` でフォルダーをゴミ箱に移動します)。それだけが目的なら、アプリや他のプロジェクトが使う DNS・証明書は残してください。

## 完全な削除を準備

DNS・TLS コマンドはデーモンの状態を参照します。準備中は CLI を利用可能にし、デーモンを実行したままにしてください。後でデーモンが再起動しないようデスクトップを終了し、稼働中のプロジェクトは名前を指定して `locdev down` で停止します。

ログイン時の起動が有効なら、実行ファイルを消す前に解除します。

```bash
locdev startup status
locdev startup uninstall
```

これはログイン時の起動設定を解除する操作で、バイナリの削除ではありません。OS ごとの詳細は[自動起動](/docs/service)を参照してください。

## DNS と TLS の信頼を解除

これらの変更は同じユーザーの LocDev 環境と、他のローカルプロジェクトにも影響します。システム連携を解除する場合だけ実行してください。提案される変更と権限の要求を確認し、自動承認は使わないでください。

デーモンが利用可能な状態で実行します。

```bash
locdev dns uninstall
locdev tls untrust
```

最初の操作は `.test` リゾルバー連携を解除し、次の操作はアプリが扱う証明書ストアからローカル CA の信頼を取り除きます。プロジェクトのフォルダーは削除しません。失敗した場合は、続行する前に状態と[トラブルシューティング](/docs/troubleshooting)を確認してください。

## 停止してバイナリを削除

準備が完了したら停止します。

```bash
locdev stop
```

デーモンと残りのプロジェクトが停止します。元の導入方法に対応するアンインストーラーまたはパッケージマネージャーを使用してください。手動展開した CLI は、選んだフォルダーの `locdev` と `locdevd` だけを削除し、`PATH` の登録も確認します。

## 残すデータを判断

設定、プロジェクト登録、ログ、管理対象ランタイム、CA のデータはバイナリと別に残る場合があります。[設定](/docs/configuration)で実際の保存先と `LOCDEV_HOME` を確認してください。手動削除の前にバックアップし、各フォルダーを確認します。プロジェクト、外部で導入した PHP・Node、共有ディレクトリは削除しないでください。

TLS の信頼を解除した後はブラウザーを開き直し、OS の自動起動設定も確認します。再導入は[インストール](/docs/installation)を参照し、異なるバージョンのデータが使えるとは仮定しないでください。
