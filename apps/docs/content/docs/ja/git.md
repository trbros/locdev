# Git、GitHub、保護

## ローカルの Git

![サイトの Git タブ: 変更されたファイルと差分](screenshot:git)

各サイトの **Git** タブは、サイトのフォルダーにあるリポジトリを、マシンにインストールされた `git` で操作します (`PATH` にある必要があります)。6 つの部分があります。

| 部分     | 内容                                                                                                       |
| -------- | ---------------------------------------------------------------------------------------------------------- |
| Changes  | 変更されたファイル (_staged_ とそれ以外に分けて表示) と各ファイルの差分。_stage_/_unstage_、破棄、コミット |
| History  | ページ送りの履歴。各コミットのファイルと差分、そこからの操作                                               |
| Branches | ローカルとリモート (upstream と ↑/↓ 付き)。作成、切り替え、現在のブランチへのマージ、削除                  |
| Stashes  | 変更の退避 (追跡していないファイルを含めるかどうか)、適用、_pop_、破棄                                     |
| Remotes  | 追加、URL の変更、削除                                                                                     |
| Activity | LocDev がそのリポジトリで実行した (または拒否した) 操作と、HEAD の _reflog_                                |

Fetch、Pull、Push は上部にあります。**Pull は常に `--ff-only`** で、勝手にマージを作ることはありません。ブランチが分岐していれば失敗するので、ターミナルか Branches タブで (merge か rebase かを) 決めてください。競合のあるマージ中は、状態を示すお知らせと **Abort merge** が表示されます。

すべてのコマンドはシェルを使わずに実行し、引数を分け、ユーザーが入力した名前の前に `--end-of-options` を置き、ブランチ名を検証します (`git check-ref-format`)。`ext::` を含む、または `-` で始まるリモート URL は拒否します。Git が対話的にパスワードを求めることはありません (`GIT_TERMINAL_PROMPT=0`、SSH は `BatchMode`)。すでに使っている SSH エージェントや _credential helper_ を使ってください。

### 元に戻す: 3 つの異なる操作

コミットの詳細には、それぞれの動作の説明とともに選択肢が並んでいます。

| 操作               | 何が起きるか                                                                                                                 | 履歴                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| **リバート**       | そのコミットを打ち消す新しいコミットを作る                                                                                   | 保たれる。共有ブランチでも安全                       |
| **ファイルを復元** | チェックしたファイルが、そのコミットの時点の内容に戻る (未コミットの変更として)                                              | 変わらない                                           |
| **Reset**          | 現在のブランチがそのコミットを指すようになる (`soft`: 変更は _staged_ のまま、`mixed`: 作業ツリーに残る、`hard`: 破棄される) | 後のコミットはブランチから外れる (_reflog_ には残る) |

その地点にブランチを作るだけの **ここに新しいブランチ** もあります。

## 破壊的な操作

![hard reset の確認: 失われるもの](screenshot:git-confirm)

次の操作は、実行前に明示的な確認を求めます。

- 変更の破棄 (追跡していないファイルの削除を含む)。
- `reset` (どのモードでも。`hard` では変更が失われるファイルも一覧表示)。
- _force push_ (常に `--force-with-lease`。リモートから消えるコミットを一覧表示)。
- 統合されていないブランチの削除。
- stash の破棄。
- 変更のあるファイルの復元。
- マージの中止。
- リモートの削除。

プレビューはデーモンが計算します。失われるもの (ファイル、コミット、stash)、先に保存されるもの、操作がブロックされるかどうか (たとえば、マージ中の `reset` や現在のブランチの削除) です。確認するには、操作ごとに決まった文言 (ブランチ名、reset 先の短い SHA、`discard`、`drop` など) を入力します。**この手順を飛ばす `--yes` はありません。** 確認はデーモンでもう一度行われるので、クライアントが回避することはできません。

### バックアップ

**先にバックアップ** がオン (デフォルト) のとき、破壊的な操作の前に LocDev は次のことをします。

- 追跡している変更の*スナップショット* (`git stash create`) と、ブランチが離れるコミットへの ref を `refs/locdev/backups/<date>-<operation>` に書き込む。
- 削除される追跡外のファイルを `~/.local/share/locdev/backups/<site>/<date>/` (各 OS での LocDev のデータフォルダー) にコピーする。

復元するには、ターミナルで `git log refs/locdev/backups/...` や `git stash apply <sha>` を使うか、Activity タブで _reflog_ からブランチを作ります。バックアップが自動で削除されることはありません。

### LocDev のパスワード

![Settings → Security](screenshot:settings-security)

**Settings → Security** (または `locdev security password`) で、破壊的な操作のためのパスワードを設定できます。

- 保存するのは **Argon2id** のハッシュだけで、設定フォルダーの `security.toml` に `0600` の権限で置かれます。パスワードがリクエストの間にメモリに残ることはありません。
- 5 回間違えると、以後の試行は 1 分間ブロックされ、間違えるたびに 2 倍になって最大 1 時間までのびます。ブロックはデーモンを再起動しても続きます。
- パスワードの変更や削除、「パスワードを求める」/「先にバックアップ」 をオフにするには、現在のパスワードが必要です。
- 復旧の手段はありません。パスワードを忘れたら `security.toml` を削除してください。保護はなくなりますが、それは目的と矛盾しません。これはうっかりミスから守るもので、あなた自身から守るものではないからです。

> [!WARNING]
> **重要な制限:** パスワードが守るのは **LocDev** (アプリと CLI) から始めた操作です。リポジトリそのものは守りません。ターミナルの `git`、エディター、ほかのツールは普段どおり動きます。

## GitHub

![サイトの GitHub タブ: ワークフローの実行](screenshot:github)

**GitHub** タブは、リモートが github.com を指しているサイトに表示されます。概要 (公開範囲、デフォルトブランチ、現在のコミットの _チェック_)、issue、プルリクエスト、ワークフローの実行、ワークフロー、リリースが表示され、項目はブラウザーで開きます。

GitHub 上で何かを変える操作は、必ず確認を求め、どのアカウントで実行するかを示します。

- **失敗したものを再実行**: 失敗したジョブを再実行します。
- **キャンセル**: 実行中のものをキャンセルします。
- **Run workflow**: `workflow_dispatch` トリガーのあるワークフローを、ブランチまたはタグで実行します。

### アカウントの接続

**Settings → Integrations** (または `locdev github connect`) で、3 つの方法から選べます。

| 方法           | やり方                                                                                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 個人用トークン | _fine-grained_ トークン (推奨。選んだリポジトリに限定できる) またはクラシックトークンを貼り付けます。CLI では引数ではなく標準入力から読みます |
| GitHub CLI     | ログイン済みの `gh` のトークンを一度だけコピーします (`gh auth token`)                                                                        |
| ブラウザー     | OAuth の _device flow_。device flow を有効にした自分の OAuth App の _client id_ が必要です。LocDev は OAuth App を配布していません            |

_fine-grained_ トークンには、_Metadata_、_Issues_、_Pull requests_、_Actions_ の読み取りを許可してください。ワークフローの再実行、キャンセル、手動実行には、_Actions_ の書き込みも必要です。

トークンは GitHub で検証され、**システムのキーリングだけ**に保存されます。Linux は Secret Service (GNOME Keyring、KWallet)、macOS は Keychain、Windows は資格情報マネージャーです。ファイルやログに書かれることはありません。使えるキーリングがない場合は、ファイルに切り替えずに接続が失敗します。デーモンがリクエストを送るのは `api.github.com` だけで、**切断** でキーリングからトークンを削除します。

### ワークフローの失敗

アカウントを接続すると、デーモンは 15 分ごとに GitHub のリモートを持つサイトの実行を確認し、新しく失敗した実行ごとに通知 (_ワークフローの失敗_ カテゴリー) を作ります。最初の確認では既存のものを記録するだけなので、古い失敗が一度に押し寄せることはありません。Integrations でオフにでき、オフラインモードでは止まります。

## コマンドラインでは

```bash
locdev git status            # ブランチ、upstream、変更されたファイル
locdev git log -n 50
locdev git branches
locdev git history           # LocDev が実行したもの + reflog
locdev security password     # パスワードの設定/変更
locdev github connect --gh   # GitHub CLI のトークンを使う
locdev github status
```

CLI はリポジトリを読むだけです。変更するには `git` そのものかアプリを使ってください。

## ワークツリー

**Git → ワークツリー** (または `locdev git worktree`) は、ブランチをリポジトリの隣の専用フォルダー (`<repo>-<branch>`) にチェックアウトし、2 つのブランチを同時に動かせるようにします。

- **独自のサイトとして登録**: フォルダーが独自のポートとプロセスを持つサイト (`<repo>-<branch>.test`) になります。
- **足りない .env ファイルをコピー**: メインフォルダーの追跡されていない `.env*` (Git には含まれない) をコピーします。上書きはしません。

```bash
locdev git worktree add feature/login --create --site-for-it --copy-env
locdev git worktree list
locdev git worktree remove ../shop-feature-login
locdev git worktree prune
```

削除は Git の他の破壊的な操作と同じく保護されます。プレビューがフォルダーと未コミットの変更をすべて示し、フォルダー名 (設定されていれば LocDev のパスワードも) を求め、追跡中の変更のスナップショットを `refs/locdev/backups/` に保存し、そのフォルダーに登録されたサイトを削除します。未コミットの変更があると、強制しない限り削除できません。ブランチとコミットはリポジトリに残ります。
