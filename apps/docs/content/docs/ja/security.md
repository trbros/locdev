# セキュリティ

LocDev は DNS、証明書、プロセスを扱うので、あまり信頼を必要としないように設計されています。

## 権限

- デーモン、CLI、アプリはあなたのユーザーとして動きます。
- システムの変更 (リゾルバー、トラストストア) は、**表示され**、**確認された**スクリプトを OS の認証の仕組みで実行するときだけ行われます。
- LocDev がシステムに書き込むものにはすべて `Managed by LocDev` の印が付き、アンインストールのコマンドはその印のあるものだけを削除します。
- ほかのツールの設定は検出して表示しますが、編集はしません。

## ネットワーク

- プロキシ、HTTPS、DNS は `127.0.0.1` (と `::1`) だけで待ち受け、ネットワークには公開しません。
- DNS サーバーは `.test` ゾーンにだけ応答し、ほかは拒否します。応答パケットは無視するので、反射のループも起きません。
- IPC は、あなたのユーザーが所有する `0700` ディレクトリ内の `0600` のソケット (Unix)、またはリモートのクライアントを拒否する名前付きパイプ (Windows) を使います。

## 証明書

- CA の鍵は、ユーザーのデータフォルダーに `0600` で保存されます。
- CA には **Name Constraints** (`test`、`localhost`) と `pathlen:0` が付いていて、ほかのドメイン用の有効な証明書や中間 CA を発行できません。
- CA の信頼は任意です。信頼しなくても HTTPS は動きますが、ブラウザーが警告します。

## プロセス

- サイトはあなたのユーザーとして、プロジェクトのディレクトリで動きます。
- サイトを停止するとプロセスツリー全体が終了するので、孤児プロセスは残りません。
- サイトを削除してもファイルは消えません。

## Git と GitHub

- Git の破壊的な操作 (reset、破棄、_force push_ など) は、失われるものを表示し、文言の入力を求めます。パスワードを求めることもできます (Argon2id のハッシュ、段階的なロック)。実行前に LocDev がバックアップを取ります。パスワードが守るのは LocDev から始めた操作だけで、リポジトリではありません。[Git、GitHub、保護](/docs/git)を参照してください。
- GitHub のトークンはシステムのキーリングだけに置かれ、ファイルやログには書かれません。デーモンが通信するのは `api.github.com` だけで、リモートでの操作はすべて確認を求めます。
- `git` はシェルを使わず、引数を分け、名前を検証して実行し、対話的に認証情報を求めることはありません。

## シークレットと認証情報

- シークレット変数はシステムのキーリングにある鍵で暗号化され (ChaCha20-Poly1305)、プロセスの環境にだけ渡されます。ファイル、引数、ログには入りません ([環境変数](/docs/environment))。
- データベースの認証情報は、デーモンが使うたびにプロジェクトから読み、IPC には流しません。リモートのデータベースは明示的に選んだときだけ開き、破壊的な SQL にはデータベース名の入力が必要です ([Database Manager](/docs/database))。

## メール

- Mailbox はループバックでキャプチャするだけで、メッセージを配信することはありません。プロジェクトの本物の SMTP を置き換えるには、あなたの同意が必要です ([Mailbox](/docs/mailbox))。
- メールの HTML は、空の `sandbox` を持つ `iframe` と、ネットワークをすべてブロックするポリシーのもとで表示されます。
- プロジェクトのコードは、あなたが頼んだときだけ (フレームワークによるプレビュー、`make:mail`)、環境を空にし、時間と出力を制限した別のプロセスで実行されます ([Email Studio](/docs/email-studio))。

## 脆弱性の報告

セキュリティの問題は、公開する前に、メンテナーに非公開で報告してください。
