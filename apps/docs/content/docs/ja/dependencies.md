# 依存関係、ジョブ、通知

## サイトの依存関係

![サイトの依存関係タブ](screenshot:dependencies)

各サイトの**依存関係**タブ (または `locdev deps list`) はプロジェクトのファイルを読みます。`package.json` と `package-lock.json`、`pnpm-lock.yaml`、`yarn.lock` (Yarn 1 と 2 以降)、`bun.lock` のいずれか、そして `composer.json` と `composer.lock` です。パッケージごとに 3 つのバージョンを区別します。

| 列               | 出どころ                                                                                     |
| ---------------- | -------------------------------------------------------------------------------------------- |
| 宣言             | マニフェストの範囲 (`^1.2.0`)                                                                |
| インストール済み | `node_modules`/`vendor` にあるもの。なければロックファイルのもの (両者が異なると `*` が付く) |
| 利用可能         | 最新の安定版。その下に、範囲内で使える最新版                                                 |

一覧表示でネットワークを使うことはありません。レジストリのデータは前回のチェックのものです。古い `bun.lockb` はバイナリなので読みません (Bun 1.2 以降はテキストの `bun.lock` を書きます)。

## チェック

**今すぐチェック** (または `locdev deps check`) は、npm レジストリ、Packagist、[osv.dev](https://osv.dev) (GitHub、npm、PHP のアドバイザリーをまとめたもの) に問い合わせます。プレリリース (alpha、beta、RC、nightly) が提案されることはありません。

更新の互換性は分類されますが、**保証はされません**。

| 結果       | 条件                                                                                                                                  |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 競合なし   | どのチェックでも問題が見つからなかった (`engines`、peer、PHP)。保証ではない                                                           |
| 可能性あり | 新しいメジャー (または 0.x のマイナー)、確認できなかった項目がある、非推奨のバージョン                                                |
| 非互換     | 要件を満たさない: サイトの Node に対する `engines.node`、インストール済みバージョンに対する peer、サイトの PHP に対する `require.php` |
| 不明       | データが足りない                                                                                                                      |

この分析で使う Node.js と PHP は、サイトが実際に使っているもの (ピン、バージョンファイル、デフォルト、`PATH`) です。

## 更新

パッケージを選んで **更新** をクリックします (または `locdev deps update <package>…`)。何かを実行する前に、LocDev は次を表示します。

- 現在 → 提案のバージョン、上がり方の種類、互換性とその理由。
- リリースノート、リポジトリ、レジストリのページへのリンク。
- プロジェクトのマネージャーとロックファイルで実行される**正確なコマンド**。
- 変更されるはずのファイル。

![確認前の更新計画](screenshot:dependency-update)

デフォルトでは、更新は範囲内にとどまります (`npm update`、`pnpm update`、`composer update --with-dependencies`)。**Allow majors** はスタイル (`^`、`~`、固定) を保ったままマニフェストの範囲を変えます。インストールスクリプト (`postinstall` など) は、オプションをオンにしない限り**実行されません**。マイグレーションやほかのコマンドも実行しません。結果にはマネージャーの出力と変更されたファイルが表示されます。

コマンドはシェルを使わず (プログラムと引数を分けて)、サイトのフォルダーで、サイトのランタイムを `PATH` に置いて実行します。

## 自動監視

**Settings → Automations** (または `locdev settings set automation.audit <value>`) で選びます: オフ、手動のみ、6 時間または 12 時間ごと、毎日 (デフォルト)、毎週。

![Settings → Automations](screenshot:automations)

- チェックは**永続的なキュー** (`data/state/jobs.json`) に入ります。予定時刻にコンピューターがオフだった場合は、戻ったときに実行されます。途中で中断されたジョブはキューに戻ります。
- サイトは時間をずらして処理され (一斉には始まらない)、各サイトはパッケージを 1 つずつ問い合わせます。すべてのジョブを合わせた 1 秒あたりのリクエスト数にも上限があります。
- レジストリのデータは 6 時間キャッシュされます。ネットワークの失敗と `429` は、待ち時間を延ばしながら (またはレジストリの `Retry-After` に従って) 再試行します。
- すでにキューにあるチェックは重複しません。
- **オフ**にすると (または**オフラインモード**をオンにすると)、キューにある自動ジョブはキャンセルされ、実行中のジョブは次のパッケージで止まります。監視のための問い合わせは続きません。
- 監視がオフでも 「今すぐチェック」 は使えます。それはあなたの依頼であって、監視ではないからです。

`locdev jobs` でキューを一覧でき、`locdev jobs cancel|pause|resume|retry <id>` でジョブを操作できます。ランタイムのインストールも同じキューで実行されます。

## 通知

![通知](screenshot:notifications)

LocDev は、利用可能な更新、脆弱性、失敗したサーバー、あなたが始めた操作の結果を知らせます。通知はディスクに保存されるので、アプリを閉じても、デーモンやコンピューターを再起動しても、閉じるまで残ります。各通知にはキーがあり、同じ更新や警告が 2 回表示されることはありません (新しいバージョンが出れば別の通知になります)。

- **未処理 / 履歴:** 既読にする、閉じる、対象を開く (サイト、依存関係タブ、サーバーの出力)。
- **設定:** 通知を作るカテゴリー (Mailbox が**キャプチャしたメール**を含む) と**システム通知** (デフォルトでオン)。LocDev のウィンドウが前面にないとき (トレイに隠れている、閉じている、ほかのウィンドウの後ろにある) は、デーモン自身が表示します。表示できなかった間に届いたものは、コンピューターが戻ったときに表示されます (複数ある場合はまとめて表示)。Linux では通知をクリックすると、一覧でクリックしたときと同じく、その内容 (サイトのタブ、Mailbox のメッセージ、アップデート) でアプリが開きます。まとめ通知は一覧を開きます。
- アプリのウィンドウが前面にあるときは、新しい通知はアプリ内のトーストとして表示され、両方が出ることはありません。アプリはフォーカスの状態をデーモンに伝えます。
- [トレイの色付きの点](/docs/app)で未読がわかります。
- すべてローカルで、外部サービスを通る通知はありません。

```bash
locdev notifications            # 未処理
locdev notifications --all      # 閉じたものも含む
locdev notifications read       # すべて既読
locdev settings set notifications.native on
locdev notifications test
```
