# サイトとプロセス

**サイト**は LocDev に登録したフォルダーで、名前、開発サーバーのコマンド、ポートを持ちます。登録内容は `projects.toml` に保存されます。LocDev からサイトを削除してもファイルは消えません。削除時にフォルダーをゴミ箱に移すことを選んだ場合を除きます (**フォルダーもゴミ箱に移動する**、または `locdev remove <名前> --delete-files`。他のサイトを含むフォルダー、ホームフォルダー、ドライブのルートは拒否されます)。LocDev の外でフォルダーが削除されたサイトは、数秒以内に停止・削除され、通知されます。外したドライブや共有上のサイトは削除されません。

一つずつ追加する代わりに、プロジェクトを置いているフォルダーを監視できます。中のプロジェクトはそれぞれサイトになり、作成と削除に一覧が追従します ([監視フォルダー](/docs/parked-folders))。

## 自動検出

フォルダーを追加すると、LocDev はマニフェスト、ロックファイル、設定ファイルを読み (プロジェクトのものは何も実行しません)、起動方法を知っているアダプターを選びます。Laravel、Next.js、Django、Rails、Vite など 45 以上のスタックに対応しています。提案されるコマンドはホスト `127.0.0.1` とサイトのポートを使い、パッケージマネージャー (`npm`、`pnpm`、`yarn`、`bun`) はロックファイルに合わせます。一覧とルールは[フレームワーク](/docs/frameworks)にあります。

コマンドはいつでも変更できます。

```bash
locdev edit blog --command "pnpm dev --port {port}"
```

## ポートと環境変数

- コマンド中の `{port}` はサイトのポートに置き換えられます。
- プロセスには `PORT`、`HOST=127.0.0.1`、`LOCDEV=1`、`LOCDEV_PROJECT=<名前>` が渡されます。
- ポートを指定しない場合、LocDev は [config.toml](/docs/configuration) の `ports` 範囲 (デフォルトは 8100–8999) から最初の空きポートを選びます。

## ライフサイクル

```bash
locdev up blog       # 起動
locdev down blog     # 停止
locdev reload blog   # 再起動
locdev logs blog -f  # 出力を追う
```

- 各サイトは専用のプロセスグループ (Unix) またはプロセスツリー (Windows) で動きます。**停止すると、コマンドが起動したものすべてが終了します** (たとえば `npm` が起動した `node`)。
- LocDev は `SIGTERM` を送り、最大 8 秒待ちます。終了しなければ `SIGKILL` を送ります。Windows では `taskkill /T /F` を使います。
- `--auto-start` (アプリでは _LocDev と一緒に起動_) を付けたサイトはデーモンと一緒に起動します。
- 出力は `logs/sites/<サイト>.log` に書かれ、`[logs] file_mb` (デフォルト 5 MB) に達するとローテーションします。デーモンは最新の行をメモリに保持し (`[logs] lines`、デフォルト 2000)、再起動後はファイルから読み直します。

## サイトのアドレス

| 項目  | 例                      | 内容                                                                   |
| ----- | ----------------------- | ---------------------------------------------------------------------- |
| URL   | `https://blog.test`     | 優先されるアドレス。CA が信頼されていれば HTTPS、そうでなければ HTTP。 |
| HTTPS | `https://blog.test`     | HTTPS が有効なら常に使えます。                                         |
| 直接  | `http://127.0.0.1:8100` | プロキシを通さない開発サーバー。                                       |

サブドメインは自動で動きます。`api.blog.test` も `blog` サイトに届きます。

## 静的サイト

`index.html` (または `public/index.html`) があり、フレームワークのないフォルダーは静的サイトです。LocDev は独自の静的サーバー `locdevd static --port {port}` (`public/index.html` の場合は `--root public`) で動かすので、Python も Node も不要です。

- 127.0.0.1 でのみ待ち受け、他のサイトと同じくプロキシの背後に置かれます (`<サイト>.test`、HTTPS)。
- クリーン URL: `/about` は `about.html` または `about/index.html` を返します。
- 存在しないファイルには、あれば `404.html` を返します。
- `Cache-Control: no-cache` なので、編集は再読み込みで反映されます。
- フォルダーの外は一切配信しません (`..`、絶対パス、エンコードされたエスケープは拒否)。

別のサーバーを使うには、コマンドを変更します: `locdev edit <サイト> --command "…"`。
