# LocDev のアップデート

**設定 → アップデート** では、アプリが新しいバージョンを探し、署名を確認してインストールし、新しいバージョンに問題があれば以前のバージョンに戻せます。デーモンと CLI はアプリに同梱されています。単体でインストールした CLI はインストールスクリプトで更新します。`locdev update` で公開済みのリリースを確認できます。

![アップデート: アプリ、デーモンと CLI、以前のバージョン。](screenshot:updates)

> [!WARNING]
> LocDev のリリースはまだ公開されていません。最初のリリースまでは、画面にリリースが見つからないと表示されます。このページの残りは、リリースができたときの動作を説明しています。リリースは公開リポジトリに置く必要があります。アプリとデーモンはトークンなしで読み取ります。

## アプリ

アプリは Tauri のアップデーターを使います。各リリースには `latest.json` と、**LocDev のリリース鍵で署名された**更新ファイルが含まれます。アプリは署名で確認できたもの(公開鍵はアプリに同梱)だけをインストールし、それ以外は拒否します。画面で選ぶのはバージョンだけで、アドレスはアプリ自身が常に GitHub 上の LocDev のリリースから組み立てます。

| システム               | アプリからの更新                                                                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Windows                | 対応(NSIS インストーラー、管理者権限の確認なし)。Windows は実行中のプログラムを置き換えられないため、インストール前にデーモンを停止します。    |
| macOS                  | 対応。                                                                                                                                         |
| Linux(AppImage)        | 対応。                                                                                                                                         |
| Linux(`.deb` / `.rpm`) | 非対応: Tauri のアップデーターは AppImage のみ置き換えます。画面にその旨が表示され、リリースページから新しいパッケージをダウンロードできます。 |

開発用のコピー(`make app`)も自動更新されません。

- **アップデートを自動で確認**(既定でオン): アプリの起動時と 1 日 1 回。新しいバージョンは通知として表示され、ボタンで画面を開けます。
- **アップデートを自動でインストール**(既定でオフ): 見つかり次第ダウンロードしてインストールします。LocDev が勝手に再起動することはありません。

インストール後、**LocDev を再起動** を押すとアプリを閉じ、デーモンを停止して新しいバージョンを開き、同梱のデーモンが起動します。サイトは一瞬停止します。

この 2 つのオプションはアプリ側(ローカルストレージ)に保存され、`settings.toml` には入りません。

## デーモンと CLI

デーモンは GitHub に公開されたリリースをトークンなしで読み取り、自身のバージョンと比較します。各リリースには、含まれるアプリとデーモンのバージョンを記した `versions.json` があります(リリースのワークフローは、アプリのバージョンと異なるタグを拒否します)。

```bash
locdev update
```

結果は 6 時間保持されます。`--refresh` で今すぐ GitHub に確認し、`--json` でスクリプト向けに出力します。

- 1 日 1 回(オフラインモード時を除く)、デーモンが自動で確認し、**新しいリリースごとに 1 回通知**します。**新しいリリースを通知** をオフにするか、`settings.toml` で `[automation] updates = false` を設定すると止まります。
- デーモンは**何もインストールしません**。アプリを使っている場合、アプリを更新するとデーモンと CLI も更新されます。実行中のデーモンがアプリ同梱のものと異なる場合(更新直後など)、画面に両方のバージョンと **デーモンを再起動** ボタンが表示されます。
- 単体の CLI は、インストール時と同じスクリプトで更新します。スクリプトはリリースの `SHA256SUMS` でファイルを検証します:

```sh
curl -fsSL https://github.com/trbros/locdev/releases/latest/download/install.sh | sh
```

```powershell
irm https://github.com/trbros/locdev/releases/latest/download/install.ps1 | iex
```

`LOCDEV_VERSION=v0.14.0` で特定のバージョンをインストールできます(戻す場合にも使えます)。

参照するリポジトリは `config.toml` の `[updates] repo` です(既定は `trbros/locdev`)。[設定](/docs/configuration)を参照してください。

## 以前のバージョンに戻す

**以前のバージョン** の **このバージョンに戻す** は、アップデートと同じ方法で古いリリースをインストールします。そのリリースの `latest.json` を使い、同じ署名検証を行います。サイト、設定、データはそのまま残ります。

古いバージョンは新しいバージョンで追加されたものを知りません。知らない設定は無視され、保存時に削除されることがあります。また、新しい形式で書かれたジョブキューと通知は、削除されずにコピー(`.broken`)として退避されます。不安な場合は、先にデーモンを停止して設定フォルダーをバックアップしてください。

## 手動で更新する

`.deb` / `.rpm` パッケージ、ローカルビルド、または手動を好む場合:

```bash
locdev version
locdev stop
```

デーモンを停止した状態で、`config.toml`、`projects.toml`、残したいデータをコピーします(パスは[設定](/docs/configuration)を参照)。ローカル CA のデータには秘密情報が含まれるため、issue や公開チャットに投稿しないでください。リリースからパッケージをダウンロードし、`SHA256SUMS` で SHA-256 を確認して、最初と同じインストーラーでインストールします。単体の CLI は `locdev` と `locdevd` を一緒に置き換えます。ローカルビルドは[インストール](/docs/installation)に従ってください。

実行ファイルのパスが変わった場合は、[ログイン時の起動](/docs/service)を見直してください。アップデートで DNS の再インストールや CA の再信頼は必要ありません。

## 更新後

```bash
locdev start
locdev version
locdev doctor
locdev list
```

起動時に `auto_start` のプロジェクトが再び開くことがあります。クライアントとデーモンのバージョンを確認し、よく知っているプロジェクトで試してください。問題があれば[トラブルシューティング](/docs/troubleshooting)を参照してください。

## 制限事項

- 実際のリリースでは未検証です(まだ存在しません)。リリースの読み取り(偽の API に対して)と画面(モックのバックエンド)はテスト済みです。Tauri アップデーターによるダウンロードとアプリの置き換えは、最初の署名付きリリース次第です。
- `.deb` と `.rpm` はアプリから更新できません。
- 戻せるのは、署名付きの `latest.json` を含むリリースだけです。
